- **深色霧面、細格線、低飽和**；金色 `#C39B6F` 是唯一的「可行動高亮」，克制使用；紅 `#893336` **只給生命/安全警示**（SOS、禁入、BLACK 傷票）
- 可讀性 > 可行動性 > 可審計性 > 可離線降級，四大原則排序不可顛倒
- 時間戳／座標／編號／計數一律**等寬字體**（數字不跳動）
- 語氣短促可回覆：ACK／派遣／結案／升級；重要事件三要素＝時間戳＋操作者＋對象
- App Shell 常駐狀態列：**Online/Offline、Sync 狀態、Outbox 待送數、最後同步時間**——這四樣是戰術介面的心跳，任何頁面都看得到

## 國際參考（研究後轉譯，不是抄）

從以下體系提取「為什麼它們長那樣」的道理，融進設計語言文件：

1. **TAK／ATAK（Team Awareness Kit）**：軍用態勢共享的地圖優先哲學、深色底圖上的高對比符號、單手快捷輪盤
2. **MIL-STD-2525／APP-6 符號學**（簡化民用版）：友軍/中立/危險的形狀語義、地圖符號的形狀＋顏色雙編碼（色盲安全）
3. **Palantir Gotham／Anduril Lattice**：現代國防軟體的資訊密度管理——深色、窄邊框、等寬數據、狀態 chip、時間軸事件流
4. **NASA/SpaceX 任務控制牆**：遙測牆的「3 秒瞄一眼」法則——大數字、趨勢箭頭、異常即高亮，正常即安靜
5. **航空 EFIS 告警層級**：Advisory（白）→ Caution（琥珀）→ Warning（紅）三級制，紅色永遠伴隨聲音/動效，且永遠最少
6. **UN OCHA／ReliefWeb／IFRC GO 平台**（go.ifrc.org）：人道資料儀表板的克制配色、災情數字的誠實呈現（不美化、不戲劇化）
7. **FEMA ICS/NIMS 表單傳統**：ICS-201/209 的欄位紀律——編號、時間、簽核鏈，這是「可審計性」的表單化
8. **台灣在地語境**：CBS 災防告警配色慣例、CAP 告警層級、消防署/NCDR 的災型圖示習慣——本平台服務台灣協會，介面是繁中優先

## 雙模式的正確詮釋（上一輪做錯的地方）

**錯誤（Phase R 現況）**：平時模式＝白底通用後台，災時模式＝同版型換深色。
**正確**：**戰術 DNA 貫穿兩個模式**，差別是張力不是身份——

| | 平時模式（Ops） | 災時模式（Tactical） |
|---|---|---|
| 定位 | 低張力戰術作業台：訓練、盤點、行政 | 全張力：應變、派遣、傷檢 |
| 底色 | 仍是深色系（可比戰時淺一階，如 `#1D2635` 主底），**絕不是白底 SaaS** | `#161E2A`＋`#080A0F` 層次 |
| 密度 | 標準 | 提高；次要資訊自動摺疊 |
| 金色 | 主要 CTA | 只剩「立即行動」（派遣/ACK/通報） |
| 動效 | 極少 | 只有告警脈動；其餘全靜 |
| 導航 | 完整選單 | 收斂到核心閉環：**回報→分流→任務→執行→結案**＋傷檢＋SOS |
| 大螢幕 | — | **TV 牆模式**（見 RWD） |

模式切換本身要有儀式感（狀態列變色＋一次性提示音格），但**不可以打斷正在進行的表單**。

## RWD 規格（四層，全部必須真實測試）

| 層 | 寬度 | 情境 | 硬要求 |
|---|---|---|---|
| **手機（外勤）** | 360–430 | 單手、戴手套、烈日/黑暗、移動中 | 觸控目標 ≥ 44px；核心動作拇指區；底部導航 ≤ 5 項；30 秒通報流在此層優先設計 |
| **平板（車載/前進指揮）** | 768–1024 | 車上顛簸、橫向為主 | 地圖＋側欄雙窗格；表格可橫捲不破版 |
| **桌機（指揮所）** | 1280–1920 | 多窗格作業 | 左導覽＋主工作區＋右側詳情/指令三欄；1440–1920 表格保持可讀 |
| **TV 牆（COP）** | 1920+ 唯讀 | 投影到指揮中心大屏，3–5 公尺外閱讀 | 「3 秒法則」：大數字、狀態色塊、自動輪播；無互動元件；`/command-center` 提供 `?wall=1` 或專屬路由 |

斷點行為必須寫進設計語言文件並逐頁驗證，**Playwright 截圖基準要涵蓋 360／768／1440 三檔**。

## 範圍與技術約束（違反即打回）

- **範圍**：全部路由頁（孤兒 36 檔刪除後約 90 頁）＋ App Shell ＋ `design-system/` 元件庫。旗艦五頁優先：指揮中心 Dashboard、30 秒通報流（`/intake`）、戰術地圖、任務派遣、傷檢（triage）。
- **技術棧不變**：React 19 + Vite 7 + react-router 7 + 既有 `design-system/` 元件體系。
- **只動視覺層**：路由結構、`page-policy`（權限單一來源）、API 呼叫、離線 outbox 邏輯**一律不動**。後端零變更。
- **Token 單一來源**：所有顏色/間距/圓角/字級改動走既有 token 檔；以 `tactical-theme.tokens.css` 為基準擴充。**硬編色防復發 gate 已存在，新增任何硬編 hex 會被 CI 擋下。**
- **a11y**：axe AA 零違規是既有基準（R4 達成過），深色戰術主題**不得倒退**——金色 on 深底、muted 文字的對比要實測，色彩語義一律配形狀/圖示雙編碼。
- **i18n 前置相容**（D11 已拍板要多語）：所有新寫的字串集中可抽取，按鈕文案遵守 `ui-copy.meta.json` 的 2–4 字＋縮寫表；**不要**硬編長句進 JSX。
- **既有測試全綠**：前端 vitest 160+、`tsc` 乾淨、Playwright 截圖基準**重新產生**（這一輪視覺全變，基準理應重拍——重拍前先跑 axe）。
